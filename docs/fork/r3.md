# Rollout routing replay (R3) through the Tinker gateway

`serve_tinker.py --use-rollout-routing-replay` makes the gateway capture the
expert routing SGLang used while sampling and replay it in the trainer, so an
MoE policy is trained on the experts that actually produced the tokens instead
of on the trainer's (numerically different) router decision. The Tinker SDKs
cannot carry the routing themselves (64k x 40 x 8 integers per datum), so the
gateway keeps it in a side store and hands the client an opaque handle.

Code: `miles/tinker/routing_cache.py` (the store), `miles/tinker/runtime.py`
(capture at sampling, materialization at unit build), `miles/tinker/server/encoding.py`
(the `routing_handle` input), `miles/tinker/core/service.py` (tenant tagging,
sweep hook). Trainer side: `docs/fork/full-finetuning.md` and the replay
managers (`miles/utils/replay_base.py`).

## Protocol

- **Sample response** (SDK 0.16.1 JSON only): every sequence carries
  `routing_id: int` (positive, < 2^53, unique per gateway process, one per
  returned sequence) next to `tokens`/`logprobs`/`stop_reason`. The proto
  response of SDK 0.27.1 drops it: proto clients keep working without R3.
- **Datum**: `loss_fn_inputs["routing_handle"]` = int64 tensor of shape `[1]`
  holding the `routing_id` of the LAST sample call merged into the datum. The
  datum's tokens (`model_input + target_tokens[-1:]`) must equal that call's
  prompt + generated tokens (including the matched stop token). Any other
  length is a `UserInputError`; a missing handle is allowed.
- **Materialization** at unit build: for every row the gateway looks the
  routing up by handle (with exact token equality), then by the exact
  full-token hash, and ships `rollout_routed_experts` (int32 `[len(tokens)-1,
  L, K]`, L = `--num-layers`, K = `--moe-router-topk`) for every row of the
  unit, DP pad rows included. Rows of a datum with no cached routing are all
  `-1`: the trainer routes those rows through the live router (never
  `arange`). Coverage is all-or-nothing per datum.
- **Policy** `--tinker-routing-replay-policy`: `natural` (default) trains
  uncovered datums with live routing and counts them; `strict` fails the unit
  with `UserInputError("datum i: R3 is enabled but no routing is cached for
  it")` (category `user`, the window is poisoned like any other user error).
- A `forward_backward` request in which no datum carries a handle logs one
  WARNING per request (`R3 enabled but no datum carries routing_handle`).

## Capture at sampling

`/generate` is posted with `return_routed_experts: true`. When a cached
sequence of the same tenant shares a prefix with the prompt (multi-turn
requests extend the previous turn's prompt + completion), the engine is asked
only for the rows past it: `routed_experts_start_len = P` with
`P = min(LCP, parent_rows)`. SGLang returns rows `[start_len, seqlen - 1)`
(`io_struct.py` `GenerateReqInput.routed_experts_start_len`,
`batch_result_processor._maybe_collect_routed_experts`), base64 int32 in
`meta_info["routed_experts"]`. The gateway decodes it off the event loop,
applies the same stop-edge trim as `miles/rollout/sglang_rollout.py` (an
extra final row is dropped; with `no_stop_trim` the stop token is part of the
returned tokens so this is normally dead), checks
`rows == prompt + generated - 1 - P`, range-checks the expert ids and stores
them as uint8 (`--num-experts` <= 256). A response without routing or with
the wrong row count fails the sample with category `server`; a sample is
never returned without its routing.

Row i of a sequence is the routing used when token i was the input (it
produced token i+1). Rows `[0, P)` of any entry sharing the prefix are
causally valid for the new request, exactly like SGLang's own radix-cached
prefix rows: SGLang reads the routing from a host buffer indexed by KV slot
(`state_capturer/base.py` `get_topk`), so the prefix rows come from whichever
request last prefilled those slots. Two consequences, both inherent (AReaL
behaves the same way):

- after a retract weight push the prefix is re-prefilled under the new
  weights, so prompt rows of an in-flight request may mix weight versions;
- an LCP parent from another trajectory (same system prompt) is equivalent to
  SGLang's radix reuse.

A datum trained twice (platoon never does this) misses the released leaf and
falls back to natural routing for the second pass.

## The cache (`RoutingCache`)

- Entries: tokens (int32 `[S]`), delta rows (uint8 `[S-1-P, L, K]`, 320 B per
  row at L=40, K=8), `parent_id`/`parent_rows`, counters. Materialization
  walks the parent chain: `rows(entry) = rows(parent)[:P] ++ delta`.
- Prefix index: blake2b digests of `tokens[:c]` at
  `c in {stride, 2*stride, ...} | {S}` (`--tinker-routing-prefix-stride`,
  256), `deque(maxlen=8)` of candidates per `(tenant, c, digest)`, refined by
  an exact longest-common-prefix compare; among equal LCPs the shortest entry
  wins so leaves stay childless and releasable.
- Lifetime: a parent found for an in-flight request is pinned until the
  sample is recorded (or fails); an entry with children is kept; a
  materialized (trained) leaf is released immediately, and a consumed parent
  follows once its last child is gone. `sweep()` (every 30 s from the lease
  sweep, and from `record()` when over the cap) applies the TTL
  (`--tinker-routing-cache-ttl-s`, 6 h, by `created_at`, leaves first) and
  the byte cap (`--tinker-routing-cache-max-bytes`, 128 GiB, LRU by
  `last_used_at` over unpinned childless entries; evicting a leaf frees its
  parent for the next round). Pinned entries are never evicted.
- Sizing: a 64k-token chain is ~21 MB (uint8) and materializes to 84 MB
  (int32). Routing must survive rollout time + `max_staleness` steps; the
  defaults cover ~4 h at 45-min steps. A gateway restart empties the cache:
  in-flight trajectories train with natural routing for one staleness window
  and the metrics show it.
- Per tenant: handles and prefixes never cross tenants.

## Metrics (`optim_step` -> platoon `optim/<key>`, `<checkpoint_root>/perf.jsonl`)

Per optim window: `routing_covered_datums`, `routing_uncovered_datums`,
`routing_uncovered_rows`, `routing_materialize_s` (materialization time of the
window's units, on the executor thread). Cumulative cache stats:
`routing_capture_rejected`, `routing_cache_entries`, `routing_cache_bytes`,
`routing_cache_pinned`, `routing_cache_evictions`. `fused_lm_head` (0/1)
reports the fused head flag. The keys are present only when R3 is on.
Run checklist: `routing_uncovered_datums > 0` is an alert; compare
`routing_cache_bytes` with the cap and `routing_cache_evictions` with the
step time to tell cap pressure from TTL expiry.

## Engine flags

`--use-rollout-routing-replay` launches the engines with
`enable_return_routed_experts` (`sglang_engine.py`) and enables the actor's
`routing_replay_manager`; `--tinker-r3-check` turns on the trainer-side
comparison of replayed vs live top-k. No EAGLE/MTP speculative decoding with
R3 (the capturer's buffer sizing ignores verify tokens). Keep
`--sglang-chunked-prefill-size 16384 >= --sglang-max-running-requests 128`.
